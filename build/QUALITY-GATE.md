# 바른 CAD 6 내부 검증 관문 (6.0.2)

일반 도면 작업 중에는 검증 프로그램을 실행하거나 메뉴를 노출하지 않는다.
정식 설치 프로그램이 임시 후보본을 먼저 실행한다. 필수 동작 검사가 실패하면
기존 프로그램 종료·제거 단계 전에 설치를 중단한다.

## 실제 실행 순서

1. `python build_desktop.py --official6`: 전체 Node 회귀 검사, Python 자산·가져오기 검사,
   독립 백엔드 검사를 실행한다.
2. `build/verify-packaged.cjs`: 묶인 실제 Electron 실행 파일을 임시 프로필에서 실행한다.
   필수 GPU/조작 검사가 실패하면 설치 파일 제작이 실패한다.
3. NSIS `customInit`: 설치 파일 안의 후보본을 임시 폴더에 푼다. 기존 승인 DB와
   보관된 검사 코드를 읽어 후보본을 검사한다. 실패/누락/건너뜀/동일·구버전/DB 손상은 차단한다.
4. 통과한 뒤에만 기존 NSIS 설치 단계를 진행한다.
5. `customInstall`: 설치된 전체 파일 해시를 후보본과 비교한다. 검사 코드와 결과를 보관한
   다음 검증 DB를 원자적으로 확정한다. 기존 항목과 검사 코드 해시는 삭제하지 않는다.

저장 위치: `%ProgramData%\Barun\CAD6Quality` 아래 `registry.json`, `probes`, `reports`.
설치된 상태에서 DB가 사라지면 HKLM 승인 표시와 대조하여 설치를 중단한다.
사용자 도면·문자·이미지를 검사에 쓰거나 서버로 전송하지 않는다.

## 누적 기준

`quality-gate-baseline.json`에 안정적인 ID와 기대 동작을 추가하고,
`quality-probe.js`에 해당 동작의 실제 검사를 추가한다. 기존 ID를 제거하거나 의미를
바꾸지 않는다. 이전 승인 검사 코드도 다음 후보본에서 다시 실행하며, 동일 ID의
어느 세대 검사라도 실패하면 차단한다. 패치 노트만 추가해서는 검사가 늘어나지 않는다.

첫 필수 항목: 클릭을 놓은 뒤 이동·다시 클릭해 선택, 직교 교차점 스냅,
F 필렛 두 클릭 및 실행 취소, R 반지름, 하단 우클릭 설정, 팝업 50%.
GPU 활성 및 렌더러 예외도 확인한다. GPU 부분 갱신·Worker 회귀는 전체 빌드 테스트에 포함한다.

## 안전한 검증 명령

설치본 자체를 설치하지 않고 검사:
`"Barun CAD 6 Setup 6.0.2.exe" /S /QUALITYCHECKONLY /QUALITYREPORT=<절대 경로>`

이 모드는 정상 검사 후 설치 단계로 넘어가지 않으며 승인 DB를 갱신하지 않는다.
정상 설치본 사용자는 이 명령을 사용할 필요가 없다.

## 범위와 한계

- 이는 누적된 동작 회귀를 차단하는 로컬 검증이다. 악성 관리자나 변조된 설치 프로그램을
  막는 전자서명/보안 경계는 아니다. 이미 배포된 구형 설치 프로그램까지 소급 통제하지 않는다.
- 이번 산출물은 정식 전체 설치본이다. 온라인 패치 서버·차등 패치 배포는 새로 구축하지 않았다.
- 실제 GPU의 합성 DOM 입력 검사이며, OS 마우스 지연이나 모든 대형 DWG의 성능을 보장하지 않는다.
- 기존 실행본은 검사 실패 시 보존된다. 검사 통과 후 Windows 파일 복사·전원·디스크 오류까지
  전체 설치 폴더의 트랜잭션 복구를 보장하지는 않는다. DB 승인 자체는 실패 시 진행하지 않는다.
- 같은 버전 재설치와 다운그레이드는 차단한다. 복구가 필요하면 승인 DB를 지우지 말고,
  원인을 확인하여 새로운 정식 버전을 검증해야 한다.
- 추가 검증 코드는 일반 설정·도면과 분리된 임시 프로필에서만 실행한다.

검증 파일: `quality-gate*.cjs/json`, `quality-install*.cjs`, `quality-verifier.cjs`,
`quality-probe.js`; 연결 지점: `desktop.cjs`, `app.js`, 정식 6 빌드 설정과 NSIS include.

## 6.0.3: 사용자가 승인한 팝업 크기 변경

사용자 요청 “이거보단 1.5배키워줘”에 따라 팝업 배율을 50%에서 75%로 변경했다.
`quality-policy.cjs`에는 이 한 건의 변경만 명시한다. 이전 6.0.2 검사 코드의
SHA-256과 이전 검사 ID를 고정하며, 다른 검사를 임의로 제외하는 옵션은 없다.

이전 검사 코드 전체를 계속 실행한다. 50% 검사의 실제 실패는 성공으로 바꾸지 않고
`superseded`, `originalStatus: failed`로 기록한다. 새 75% 검사가 통과해야만 승인한다.
이전 기준과 사용자 요청 및 변경 이력은 DB에 보관한다. 나머지 스냅·필렛·선택 검사와
새 검사에서 발생하는 오류는 계속 설치를 차단한다.
