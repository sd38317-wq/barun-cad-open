# MLightCAD 연결 검증

## GPU 공간 분할 적용 (2026-09-26)

`gpu-spatial.js`의 BVH가 GPU 묶음 경계를 검색한다. 선 스타일별 전체 도면 버퍼를 최대 512개 선분의 공간 묶음으로 나누고 화면과 겹치는 묶음만 THREE 장면에 연결한다. 문자 묶음은 겹침 합성을 위해 원래 순서를 유지한다. 해치 경계는 실제 생성 형상에서 계산한다. 선 추가/이동/삭제의 증분 갱신과 기존 두 번 클릭 선택 동작을 유지한다.

`spatial-check.cjs`는 숨김 시험창에서 병원 복사 도면의 5개 시점을 검증한다. 확대 중앙의 처리 선 수는 243,631→50,772, 가장자리 확대는 244,623→19,289이다. CPU 렌더 호출 중앙값은 중앙 0.8→0.6ms, 가장자리 0.5→0.3ms, 전체 보기 3.6→5.5ms였다. GPU 완료 시간이나 실제 입력 지연/FPS 수치가 아니다. 전체 보기에는 묶음 수 증가 비용이 있다.

공간 제외를 켠 화면과 같은 형상을 전부 그린 화면을 비교했다. 700,000픽셀 중 차이 최대318픽셀, 채널 차이 최대8/255로 명시적 허용 기준(차이≤0.1%, 채널 차이≤10)을 통과했다. 반복 전체 렌더링도 일부 차이가 있지만, 모든 차이가 잡음이라고 입증된 것은 아니다. 완전한 픽셀 동일성을 주장하지 않는다. 결과 `spatial-results.json`. 관련 단위·회귀 52개 통과, 독립 검토 지적 수정 완료.

비교판들은 현재 단일 실행 프로필을 공유한다. 종료 시 `close-backups`에 현재 도면을 보관하며 `--restore-latest`로 복원한다. 이전 아래 기록의 별도 창/프로필 실행 설명은 과거 동작이다. 설치 파일·배포는 하지 않았다.

## 명령 완료 뒤 첫 이동 지연

선 명령의 두 번째 점→Esc→즉시 pointermove→다음 paint 순서를 실제 앱 이벤트로 재현했다. 단순 객체 변경을 증명하는 engine COW delta를 GPU에 전달한다. 추가는 작은 배치만 업로드하고 이동/삭제는 영향받는 스타일 배치만 갱신한다. 문서/리비전/스타일/표시 순서 검증 실패, 복합 객체와 undo 등은 전체 재구성한다.

`post-command-check.cjs`는 표시된 비활성 시험창에서 병원 도면에 선을 3회 추가한다. `--full-rebuild`는 시험 서버에서 delta 전달만 차단하여 같은 조건의 전체 재구성을 비교한다. 완료 입력부터 첫 paint 뒤 timer까지 391~491ms → 37~57ms (`post-command-full-results.json`, `post-command-results.json`). OS 디스플레이 완료 시간은 아니며 작은 선 추가의 3표본이다. 처음 숨겨진 창 결과는 RAF 제한이 섞여 직접 비교에 쓰지 않는다.

정상 IndexedDB 복구와 중복되던 localStorage 직렬화를 생략하고, 입력 중 예약 저장은 입력이 멈춘 뒤 실행한다. IndexedDB 오류/혼합 대용량 탭에서는 기존 localStorage fallback을 유지한다. 종료/숨김 시 명시적 flush는 유지한다. 복구 snapshot의 중복 structuredClone은 제거하며 IndexedDB.put의 즉시 복제를 사용한다.

`open-comparison.cjs --post-command-check`: 별도 프로필·18782 포트. 단위/회귀 검증 68개 통과. 모든 편집 성능 해결은 아니며 대형 기존 스타일 이동/삭제와 복합 객체·undo는 비용이 남는다.

## 명령 중 스냅 지연 수정

`command-check.cjs`는 병원 복사 도면에서 SELECT/MOVE/COPY/LINE/PLINE 시작과 각 20회 포인터 이벤트를 측정한다. 프로파일링에서 snap 및 교차점 조합 비교가 병목이었다. snap-intersections.js는 커서 허용 영역에 선을 잘라 만든 후보 경계로 조합을 거른 다음 기존의 정확한 교차점 계산을 수행한다. 후보 개수 제한이나 스냅 비활성화는 하지 않는다.

프로파일링을 켠 동일 시험의 전/후 (`command-before.json`, `command-results.json`): LINE 이벤트 평균 78.89→10.04ms, 최대 671.1→87.2ms; PLINE 평균 77.90→6.23ms, 최대 703.1→52.6ms. 이는 20개 표본의 동기 이벤트 처리 시간이며 전체 프레임/실사용 지연이나 모든 도면의 보장은 아니다. 선택 이후 GPU 전체 재생성 비용은 이번 수정 범위 밖이다.

`open-comparison.cjs --snap-check`는 18781 포트의 별도 프로필에서 명령 속도 수정판을 연다.

## 두 번 클릭 선택 수정

빈 바닥을 클릭하고 손을 뗀 뒤 선택창을 움직여 다시 클릭하는 기존 선택 방식을 유지한다. 첫 클릭의 1px 흔들림을 객체 끌기 기준(.5px)으로 처리해 선택창이 즉시 끝나던 경우를 재현하고, 선택창 클릭 판정만 4px로 분리했다. 객체/그립 끌기 기준은 유지한다.

`pointer-check.cjs`는 별도 Electron 창에서 GPU 활성 상태의 MOVE/COPY/ERASE 두 번 클릭 선택을 검증한다. 결과는 `pointer-results.json`. 실제 사용자 입력 지연이나 대형 도면 성능 측정은 아니다. `open-comparison.cjs --selection-check`는 기존 창을 보존하고 18780 포트와 별도 프로필로 수정 비교판을 연다.

전용 의존성: three-renderer 1.7.1 / Three.js 0.172.0. 기존 3D의 Three.js 0.186.0은 유지.

`node tools/gpu-renderer/build.mjs`로 vendor/mlightcad.js 생성. 전용 package-lock.json으로 버전 고정. 법적 주석은 vendor/mlightcad.js.LEGAL.txt에 보존. 의존성 라이선스 목록 dependency-licenses.json.

## 실제 연결
app.js → gpu-controller.js → gpu-renderer.js → MLightCAD AcTrRenderer.
gpu-scene.js는 기존 편집 문서를 표시 형상으로 바꾸며, gpu-fills.js는 native 해치 셰이더를 연결한다. 한글 문자는 기존 글꼴로 아틀라스를 만들어 GPU에 보관한다.
기존 화면/GPU 화면 버튼으로 전환. 일반 시작은 기존 화면 유지, 비교 실행은 GPU 활성화. GPU 실패나 미지원 객체는 전체 도면을 기존 화면으로 돌리고 버튼 설명에 이유 표시.

## 검증 결과 (2026-09-26)
병원 DXF → 기존 importer의 내부 객체 18,001개 → 표시 기본 도형 128,712개.
최종 30회 이동 그리기 호출 시간: 기존 p50 48.1ms / p95 61.4ms, GPU p50 6.9ms / p95 7.7ms. 두 경로 전체 도면을 같은 위치에서 그림. 실제 기존 앱의 화면 밖 객체 제외와의 비교, 스냅·입력 지연·GPU 완료 시간 또는 전체 FPS 측정은 아님.
Electron WebGL 하드웨어 활성화 확인. 전체 배치 이동에서 GPU 재생성 없음.
실제 app.js에서 추가/복사/삭제/undo/문서 교체/팬 확인. 단위·회귀 테스트 18개 통과. 원본 DWG/DXF와 설치 앱 미수정.

## 남은 제한
편집 리비전마다 전체 GPU 장면 재구축: 이 도면에서 약 278~357ms + 첫 그리기 약 84~105ms. 객체별 증분 갱신과 스냅 성능 개선은 아직 미구현.
XCLIP, 문자 배경 마스크, 여러 줄 가운데/오른쪽 정렬, 한도 초과 형상은 전체 Canvas fallback. 기본 도면은 GPU이나 선택 강조·그립·명령 미리보기는 기존 Canvas.
해치 밀도 표현/곡선 분할/문자 아틀라스의 픽셀 표현은 기존 Canvas와 완전히 같다고 검증하지 않음. 시험 연결이므로 제품 기본값은 아직 변경하지 않음.

실행: Libre/QCAD와 별개로 바른 CAD GPU 비교.lnk. 병원 내부 문서의 복사본으로 시작. 서버/프로필 분리. 설치 패키지 또는 배포 없음.
