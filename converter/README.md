# Barun CAD embedded DWG/DXF converter

ACadSharp 3.8.0 (MIT), with a self-contained .NET 8 win-x64 runtime.
No installed AutoCAD, ODA File Converter, or machine-wide .NET is used.

Build with a .NET 8 SDK:

    dotnet publish converter/BarunConverter.csproj -c Release -r win-x64 --self-contained true -p:RuntimeFrameworkVersion=8.0.31 -o dwg-runtime

Pin the runtime (8.0.31) so a refresh changes only BarunConverter.dll.
For win-* runtimes the project trims the .NET framework assemblies (TrimMode=partial: ACadSharp and this program stay whole, so the reflection in LineSplit.cs and the anonymous-object JSON keep working) and precompiles them (ReadyToRun), and the publish drops the debugger/crash-dump helpers: 45 files, 27MB instead of 191 files, 73MB, no .pdb. Publish into an empty folder and copy the three license files back. After any change to these settings, compare outputs against the previous runtime on real drawings (identical DXF apart from the $TDUCREATE/$TDUUPDATE/$TDINDWG time stamps). macOS publishes (build_mac_runtimes.py) are not trimmed. NativeAOT (one 11MB exe) was tried and rejected: large drawings converted up to 56% slower.

Keep ACadSharp-LICENSE.txt, DOTNET-LICENSE.txt and DOTNET-THIRD-PARTY-NOTICES.txt in dwg-runtime when refreshing the binaries.
build_desktop.py bundles that directory. The separate acadrust auxiliary converter is built from converter-rs and bundled under acadrust-runtime.

Input/output versions: 2000, 2004, 2010, 2013 and 2018. AutoCAD 2020/2025 use the 2018 DWG format (AC1032); there is no separate 2020 DXF option here.
Each output is read back; model-space entity counts must match. With a fourth argument `--defer-verify` (used by the DWG importer, which reads the DXF anyway) the engine skips its own read-back and always reports `inputTypes`; batch_converter.py then compares per-type counts on the document it read and falls back to acadrust on any mismatch. Without `--defer-verify`, drawings containing entity types this ACadSharp version cannot write to DXF (REGION and TABLE) fail before writing, so the verified acadrust fallback starts immediately. With it the output is written anyway: when neither engine carries every object, the importer opens the reading that lost the fewest objects and tells the user which types and counts are missing (file conversion stays strict). ACadSharp 3.8.0 still cannot write TABLE entities to DXF (3.7.1 also dropped WIPEOUT), and drops INSERTs whose block definition is missing in the source; those are reported as `invalidTypes`, not as lost objects. This does not prove complete semantic fidelity, especially for unsupported custom objects, external references or fonts. Reader/writer notifications are returned to the user.
With `--split-lines <file> [--split-min n]` (import only, requires `--defer-verify`) plain model-space LINEs, CIRCLEs, ARCs and straight LWPOLYLINEs are written to a compact binary file instead of the DXF when there are at least n of them (default 20000); the layout is documented in LineSplit.cs and read by `exchange.read_split_lines`, which builds exactly the entities the DXF route would (checked field by field on real drawings, including the fingerprints). Entities with an extension dictionary, reactors, thickness, transparency, invisibility, a colour book, polyline bulges or vertex widths stay in the DXF; so do circles, arcs and polylines whose normal is neither exactly +Z nor exactly -Z (a -Z one is flagged and flipped by the importer exactly as ezdxf.upright does). Lines are split whatever their normal: their coordinates are WCS. Split entities are not part of the source-preservation DXF: an export rewrites them from the drawing (same geometry and properties) without their XDATA. If the line file and the DXF do not line up, the importer imports the drawing again through the DXF alone.

With `--dyn-blocks <file>` the converter writes dynamic definitions (`ACAD_ENHANCEDBLOCK`) and per-reference values (`AcDbBlockRepresentation`) to JSON. Supported definitions are linear, visibility, flip, rotation and XY; actions are stretch, move, flip and rotate. The importer attaches them to `sharedBlocks[name].dynamic` and `reference.dynamic`. DYNB recomputes only the selected reference as an inline block and preserves its attached attribute text. Unknown visibility names match without case/whitespace first, then fall back to the first state with an in-dialog notice. A block with unsupported evaluation nodes stays unchanged.
Python stages input/output in isolated temporary directories, limits files to 30MB and time to 90 seconds, and writes results with exclusive creation to preserve existing files.

Import-only decomposition (--defer-verify, DXF output): TABLE is lowered to one INSERT containing cached boundary/text primitives, or generated cell grid LINEs and MTEXT when no usable graphics cache exists. Insertion point, normal, rotation, scale and merged-cell boundaries are retained. Generated cell layouts are a basic rendering: backgrounds, data links and formulas are not retained as table behavior; block-only cell content without rendered text is left unresolved. The conversion reports original inputTypes, transformed expectedOutputTypes (DXF names, before split-lines), and decomposedTypes counts. REGION ACIS payloads are forwarded in `acisRegions` (base64 data, `binary`, owner block and entity properties); Python recovers closed polygonal boundaries from SAT/SAB (unsupported curve edges remain unresolved) and otherwise keeps the existing missing-type/fallback notice. No decomposition runs for strict file conversion or DWG output. Unresolved table/region entries are reported in `unresolvedDecompositions` with owner block, type and count, including entities inside block definitions.

`acisRegions` entries contain handle, ownerBlock, layer, ACI color, optional `trueColor`, lineweight, linetype, data, and `binary`. They are import metadata only and are not a promise that every ACIS curve can be recovered.

Dimension compatibility (ACadSharp 3.8.0):

- DWG already stores DIMORDINATE HorizontalDirection. The upstream DXF writer omits group 51; DimensionDxfWriter inserts it during the output stream for nonzero ordinate directions, including block definitions and paper space. Drawings without rotated ordinates use the original writer. No read-back pass is added.
- LARGE_RADIAL_DIMENSION / AcDbRadialDimensionLarge is absent from the installed entity types and internal reader/writer dispatch. Offline NuGet cache has only 3.7.1 and 3.8.0. A newer package or complete source fork is needed for native support; no package was downloaded. Adding an external subclass cannot extend the internal DWG dispatch.
- batch_converter.py stages jogged dimensions as supported radial DIMENSIONs with the same handle, order, style and dimension picture. BARUN_JOGGED_RADIUS XData stores override center / jog WCS coordinates (1011) and jog angle. exchange.py recovers our parametric jogged dimension without BARUN_CAD_V2. The exported DXF remains native LARGE_RADIAL_DIMENSION. Native AutoCAD jogged-radius editing is not provided by this fallback; dimension regeneration can replace its picture. Calling BarunConverter.exe directly on an unstaged jogged DXF fails explicitly instead of silently dropping it.
- DIMBREAK keeps the broken dimension picture and BARUN_DIMBREAK XData, alongside the earlier BARUN_DIMENSION_BREAKS XRECORD. Large payloads stay in the owned XRECORD with an XData handle pointer, within a conservative 16 KiB bound. This is our persistence format, not AutoCAD AcDbBreakData. AutoCAD regeneration / dimension edits can still remove the visible gaps.

No verifiable DXF field schema or local example of AcDbBreakData / AcDbBreakPointRef was found in the repository, node_modules, ezdxf or installed ACadSharp. Do not fabricate ACAD_DIMBREAK records. To implement native persistence, obtain an AutoCAD-created ASCII R2018 DXF and corresponding DWG containing a linear dimension with (1) a manual break, (2) an automatic break against a simple LINE, plus saves after REGEN and after moving the cutting LINE. Keep extension dictionaries, OBJECTS, CLASSES, reactors and cutter handles intact. AutoCAD / ODA File Converter were not found on this host, so external application interoperability remains unverified.

Evidence: [ACadSharp 3.8.0 DWG dimension writer](https://github.com/DomCR/ACadSharp/blob/v3.8.0/src/ACadSharp/IO/DWG/DwgStreamWriters/DwgObjectWriter.Entities.cs), [DXF dimension writer](https://github.com/DomCR/ACadSharp/blob/v3.8.0/src/ACadSharp/IO/DXF/DxfStreamWriter/DxfSectionWriterBase.Entities.cs), [DXF reader dispatch](https://github.com/DomCR/ACadSharp/blob/v3.8.0/src/ACadSharp/IO/DXF/DxfStreamReader/DxfSectionReaderBase.cs), [Autodesk BreakPointRef API](https://help.autodesk.com/cloudhelp/2019/ENU/OARX-RefGuide/files/OREF-AcDbBreakPointRef.html).

Focused verification: python -m pytest test_dimension_extra_exchange.py -q (also exercises raw native group 51, five DWG versions, block/paper space, 30 stream chunk/encoding combinations, source immutability, XData-only reopening and large XRECORD payloads). Refresh only the converter into dwg-runtime with the pinned publish command above; do not run build_desktop.py for this change.

동적 블록 작업 범위와 저장 조사:

- DYNB는 명령을 열 때만 모듈을 읽는다. 동적 정의가 없는 도면에는 새 매개변수 해석을 추가하지 않는다.
- 회전은 내부에서 라디안, 화면에서 도를 쓴다. XY는 가로·세로 길이만 도면 단위에서 mm로 바꾼다. 대칭 상태 번호와 각도는 길이 배율을 곱하지 않는다.
- 대칭의 원본 참조 캐시 형식은 확인하지 못했다. 변환기는 현재값을 null로 내보내고, 화면은 사용자에게 상태를 직접 고르게 한다. 미선택 상태로 다른 값을 적용해 기본 모양으로 되돌리지 않는다. 대칭 현재값 자동 읽기는 미완성이다.
- 회전 기준점과 대칭축은 정적 정의 범위만 지원한다. 다른 매개변수로 기준점·축을 바꾸는 연결은 해석이 확인되지 않아 미지원으로 표시한다. 조회표도 값 묶음과 연결의 원본 파일 형식이 검증되지 않아 지원하지 않는다. 미지원 노드가 있는 정의는 재계산을 막고 원본 모양을 유지한다.
- 새 종류 검증은 코드로 만든 정의·캐시를 사용한다. 생성 표본을 실제 DXF로 쓰고 다시 읽는 조사에서는 저장·읽기는 성공했지만 동적 정의와 참조 연결이 모두 사라졌다. 이 경로로 원본 그래프 읽기를 검증했다고 볼 수 없다. 실제 원본 DWG와 외부 편집 프로그램의 상호운용 검증은 별도다.
- 저장 시 동적 그래프 되쓰기는 구현하지 않았다. DWG 가져오기는 먼저 DXF로 바꾸고 이 변환 결과를 원본 보존 데이터로 담는다(exchange.py의 _import_source). JSON에는 화면용 매개변수·동작만 남아 원본 그래프 객체, 확장 사전, 핸들 연결 전체가 없다. DYNB 변경 참조는 일반 BLOCK/INSERT/ATTRIB로 저장되며, 저장 후 동적 연결을 복구할 정보가 부족하다.
- 안전하게 확장하려면 원본 그래프와 관련 사전·핸들 전체의 무손실 읽기/쓰기를 먼저 검증해야 한다. 그 뒤 원본 보존 데이터, 익명 *U 정의, 참조의 AcDbBlockRepresentation 및 캐시를 하나의 객체 그래프로 유지하고, 저장→재열기→수정→재저장→재가져오기에서 정의·상태·속성·연결을 검증해야 한다. 현재 객체 수 비교만으로는 이 무결성을 보장할 수 없다.

관련 시험: node --test dynamic-block.test.js, python -m pytest test_dynamic_block_exchange.py test_converter_dynamic_parameters.py test_acad200_block_exchange.py -q.

- 블록 재정의로 참조 캐시의 노드 번호가 정의와 달라지면 캐시 종류를 증명할 수 없어 현재값을 null로 보존한다. 이전 점쌍을 길이·각도·가로·세로로 추측하지 않으며, 해당 회전·가로·세로 값의 자동 복구는 지원하지 않는다. 미지원 종류의 캐시도 다른 매개변수에 재사용하지 않는다.
- 가로·세로 매개변수의 대표 이름은 요소 이름(ElementName)을 쓰고, 없으면 ‘가로·세로’로 표시한다. 각 축의 이름은 별도로 유지한다.
